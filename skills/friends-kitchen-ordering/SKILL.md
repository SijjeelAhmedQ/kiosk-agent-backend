# Ordering at Friends Kitchen

This skill drives the errand agent that already exists in this repository. It
adds no ordering logic of its own: every script here calls the same entry point
a person or the control panel would call, so what the agent does and how it
decides are unchanged.

**Never place an order by calling the Friends Kitchen REST API directly.** The
cash limit is enforced inside `authorize_payment` in `agent/tools/api_tools.py`,
not by the prompt and not by the caller. Going round the agent goes round the
only thing stopping an overspend.

## Which route to take

| Situation | Route |
| --- | --- |
| The service on 8100 is running, or the console is open | `scripts/place_order.py` |
| No service, a terminal, and this repository's `.venv` | `python run.py "<errand>" --coupon <code> --limit <rupees>` |
| Watching the trace matters | either — both stream the same events |

Both build the same agent through `agent/friends_kitchen_agent.build_agent`.
The HTTP route is preferred because it serialises runs: the wallet, the cart and
the browser are one-per-process, so a second concurrent errand would share the
first one's basket. `server.py` holds a lock; two shells do not.

## Before you send it out

Run `scripts/check_ready.py`. It reports four things that each stop an errand
dead, and says which one is wrong:

* the ordering service itself,
* the Friends Kitchen REST API it buys from,
* whether the selected LLM has usable credentials (`hasApiKey`,
  `credentialProblem`) — change the selection with the
  `friends-kitchen-llm-configuration` skill, not by editing `.env`,
* which courier a delivery would go to, if this errand is a delivery.

Then run `scripts/list_coupons.py` if a coupon was named but not verified.
Spent, expired and cancelled coupons come back too, labelled — a coupon that is
"not working" is nearly always one of those rather than a typo.

## Sending it out

```
python skills/friends-kitchen-ordering/scripts/place_order.py \
  "Order two cheeseburgers and a large drink" \
  --coupon FK-8H2K-9QW1 --limit 2500
```

The errand needs a coupon, a cash limit, or both; with neither the service
refuses with 422 before the agent is built. Add `--mode browser` to drive the
real website in Chromium instead of the REST API — same six steps, different
hands. Add `--lat`/`--lon` to make it a delivery.

The script prints the trace as it arrives and then the agent's own report, and
exits non-zero if the run failed. See `references/ORDERING-FLOW.md` for what
each step in that trace means and `references/HTTP-API.md` for the wire format
underneath it.

## The order of operations is not negotiable

1. Find the product — ids are generated by the restaurant and cannot be guessed.
2. Add to cart.
3. Check the coupon **while the cart can still be changed**.
4. Place the order (this creates it; it does not pay).
5. Apply the coupon to the placed order.
6. Authorize payment — the step that spends money.

An order that reaches step 4 and stops is placed and unpaid, and somebody has to
settle or cancel it. If a run ends between 4 and 6, say so plainly rather than
reporting the errand as clean; the ordering agent's own brief says the same, and
`scripts/place_order.py` prints the wallet summary either way.

## Delivery

Passing `--lat`/`--lon` turns a counter order into a delivery. Three things
change and nothing else does:

* `check_delivery_location` joins the toolset, and the agent calls it first to
  learn which branch serves the customer.
* The order is placed as `take_away`. A dine-in order gets no rider.
* The handover is automatic — `authorize_payment` hands a paid take-away order
  to the courier and reports the job it created.

**A handover starts a delivery; it does not complete one.** Only the status
`delivered` means the food is with the customer. Track it with the
`friends-kitchen-delivery-dispatch` skill.

## Money

Every figure in this system is Pakistani rupees, already formatted as `Rs 1,093`
by the tools. Never convert one, never divide by 100, never write `$`, `USD` or
a bare number where an amount belongs. `references/MONEY.md` has the rest,
including what the wallet actually enforces and what it does not.
