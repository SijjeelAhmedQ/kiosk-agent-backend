# The errand, step by step

What the ordering agent does and which tool does it. Read this when a trace
needs interpreting, or when deciding whether something can be done at all —
the tools listed here are the entire vocabulary the agent has.

Source of truth: `agent/tools/api_tools.py`, `agent/tools/browser_tools.py`,
`agent/tools/delivery_tools.py`, assembled in `agent/friends_kitchen_agent.py`.
Nothing in this skill changes any of it.

## Two hands, one sequence

`build_agent(wallet, mode=...)` swaps the toolset and nothing else. Both
toolsets are shaped the same way on purpose, so the brief and the steps are the
same either way.

| Step | `mode="api"` | `mode="browser"` |
| --- | --- | --- |
| See the categories | `list_categories` | `list_categories` |
| Find a product | `browse_menu(search, category_id)` | `search_menu(term)` / `open_category(id)` |
| Open the site | — | `open_friends_kitchen(order_type)` |
| Look at the screen | — | `read_screen` |
| Add | `add_to_cart(product_id, quantity, as_meal)` | `add_to_cart(product_id, quantity, as_meal)` |
| Inspect the cart | `view_cart` | `read_screen` |
| Remove a line | `remove_from_cart(line_id)` | — |
| Check the coupon | `check_coupon` | — |
| Go to checkout | — | `go_to_checkout` |
| Place the order | `place_order(order_type, payment_method)` | — |
| Apply the coupon | `apply_coupon` | `apply_coupon` |
| Pay | `authorize_payment` | `pay(method)` |
| Look one up | `get_order(order_number)` | — |

Browser mode collapses placing and paying into `pay`, because the website does.
The API toolset keeps them apart, because the API does.

## The six steps that matter

1. **Look the product up.** Ids are generated by the restaurant. A guessed id
   is the single most common way a run fails, and it fails several calls later
   as "product not found".
2. **Add to cart.**
3. **Check the coupon while the cart can still be changed.** After step 4 the
   cart is an order, and changing it means placing another one.
4. **Place the order.** This creates it. It has not been paid for.
5. **Apply the coupon to the placed order.**
6. **Authorize payment.** This is the step that spends money.

A run that stops between 4 and 6 has left a real, unpaid order behind. That is
worth saying out loud rather than reporting the errand as clean.

## What the agent is not allowed to do

* Invent a product id.
* Retry an unchanged payment the cash limit already refused. The refusal is
  arithmetic, and it will refuse identically. Remove items or apply the coupon.
* Place a second order to work around a refusal.
* Add anything nobody asked for, or upgrade an item to a meal unasked.

The first is a prompt rule; the rest are enforced in `agent/wallet.py` and in
`authorize_payment`, so they hold whatever the model decides.

## Delivery

The delivery tools join the toolset only when the errand was started with a
customer location — an errand with nowhere to deliver to is not offered a tool
it cannot use.

| Tool | What it does |
| --- | --- |
| `check_delivery_location` | Which branch serves the customer, and how far. Call before placing the order so it is placed where a rider can collect it. |
| `arrange_delivery(order_number, notes)` | A **retry**, for when the automatic handover failed. Not the normal route. |
| `check_delivery` | Where the delivery has got to. |

The customer's position is not something the agent supplies or can change: it
was given to the errand when it started, and the tools read it directly.

**The handover is automatic.** `authorize_payment` hands a paid `take_away`
order to the courier and reports the job it created. There is no step for the
agent to remember and none to skip. If the handover fails, the payment tool
says so in the same breath as the charge — the order is still bought and paid
for, and both halves have to be reported.

`delivered` is the only status that means the food is with the customer. See
the `friends-kitchen-delivery-dispatch` skill.

## Events on the run's stream

`server.py` emits these, and `scripts/place_order.py` renders them:

| `type` | Carries |
| --- | --- |
| `status` | `queued` (with `queued: true` when a run is in front of it), `running`, `cancelled` |
| `location` | The customer, the branch serving them, the distance, the courier |
| `browser` | `opened` / `closed`, browser mode only |
| `tool` | `toolUseId`, `name` — announced once per call |
| `tool_result` | The tool's own return value |
| `text` | A fragment of the agent's prose, as it is composed |
| `final` | The report, and the wallet summary |
| `error` | One sentence, written for a person |
| `end` | Always last |
